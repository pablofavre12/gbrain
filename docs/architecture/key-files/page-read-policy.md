# Key files: Page read policy

[Subsystem index](../KEY_FILES.md). Read this contract before changing shared page authorization.

- `src/core/search/read-policy-sql.ts` — shared internal concrete-page SQL policy (`PageReadScope` in `types.ts`): nonempty federated grants precede scalar source; `excludePrivate` is resolved by `ops/context.ts:readPolicyOpts`, never an MCP override. Optional live-page filtering excludes deleted/quarantined pages and archived sources. Both engines apply policy inside content, version, timeline, graph and identity reads before limits. While page privacy is enforced, history requires both current-page and snapshot visibility. Links/timeline projections independently authorize originating pages.

- `src/core/search/page-acl.ts` and `src/core/engine-sql/page-acl.ts` — common row ACL policy for bound SQL and composed fragments. Remote atoms require a live origin in the same source with a matching stable `derivation_inputs` page ID; both the atom and origin must admit the reader. Missing, replaced, unbound or chained origins fail closed. Synthesized concepts check their recorded inputs with the same rule. This policy is independent of private-page opt-outs. Chunk rows and pagination counts share it. Legacy unbound derived pages remain readable locally; recompute from the original canonical inputs into fresh derived identities with operator-approved model spend to establish provenance, never infer identity from a reused slug. Existing completion checkpoints may skip legacy outputs; visibility repair alone does not establish an input binding. Tests: `test/derived-page-acl.test.ts` and its PostgreSQL wrapper.
