# Upgrade to v0.60.238.0: rebuild authored references after the fork upgrade

This guide applies to the fork release based on upstream v0.60.237.0. Schema
migration alone does not make reference reads ready: existing pages also need
current authored-reference inventories. Until then, scoped reads can return
`projection_pending`.

**Say to your agent:** *"Check this fork upgrade and rebuild authored references for the approved sources."*

1. **Confirm the upgrade target and approval.** Use the reviewed fork commit in
   the deployment wrapper. Coordinate all writing CLIs with that revision,
   pause writers, and verify a restorable database backup and isolated upgrade
   rehearsal before an authorized production rollout. Do not substitute an
   upstream install or treat this guide as deployment permission.

2. **Apply migrations on the approved brain host.**
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   gbrain doctor --json
   ```
   The fork bookmark must reach `9010` and the independent upstream cursor
   `245`. A failure or incompatible populated vector dimension stops the
   upgrade. Do not clear vectors, change embedding providers or renumber
   historical fork migrations to get past a refusal.

3. **Preview and rebuild the intended sources.** Replace `<source-id>` with
   each approved source, keeping the same scope for preview and execution:
   ```bash
   gbrain extract --stale --include-frontmatter --source-id <source-id> --dry-run --json
   gbrain extract --stale --include-frontmatter --source-id <source-id> --json
   ```
   Include frontmatter explicitly; its default is off. The command uses the
   database, so it also works for sources without a filesystem checkout. It
   refreshes derived links, timeline entries and mentions as well as authored
   references. Do not change extraction models, provider credentials or source
   visibility as part of this backfill.

4. **Verify completion before resuming writers.** Inspect the extraction
   result for remaining work and refused or skipped pages. Repeat the same
   bounded command when its time budget expires; investigate failures or
   persistent skips. A successful command with remaining work is not complete.
   Check `gbrain doctor --json` and representative authorized reference reads
   for every intended source. Do not report readiness while a required read
   still returns `projection_pending`.

5. **Preserve confirmation and publication boundaries.** Existing pending
   write proposals without a base revision require a fresh preview before
   replacing a page. Previously accepted public timeline entries are not
   automatically withdrawn if their original evidence later becomes private.
   Restoring an older image does not undo database migrations; use the tested
   backup restoration procedure if rollback is authorized.

See [the fork contract](../../FORK.md) and [temporal graph permissions](../../docs/guides/temporal-edges.md#reader-permissions).
